# EhealthFog v1.1.0: criticality-aware task offloading for e-health monitoring in iFogSim2

Code and data for the revised manuscript *Reducing Latency in Critical E-Health Scenarios: A Priority-Based Task
Offloading Heuristic for Edge–Fog Computing* (Torres, Cueva and Loja, submitted to *Sensors*).

## Base simulator

iFogSim2 on CloudSim 7.0, commit `5f68d39` of <https://github.com/Cloudslab/iFogSim> (October 2025). The
upstream sources under `src/` are unmodified; all changes are in the package below.

Version `v1.1.0` is the version used in the revised manuscript. The first submitted version, `v1.0.0`
(Zenodo, DOI 10.5281/zenodo.22718178), contained two configuration errors described in `CHANGELOG.md` and in
the response to the reviewers; its results must not be used.

## Contents

```
src/org/fog/test/perfeval/ehealth/
  CriticalityAwareFogDevice.java   per-tuple forwarding decision (Algorithm 1), fair CPU sharing, exact completion
                                   times, unicast Fog->Edge results, sliding-window utilisation, energy and bytes
  EhealthFogV2.java                scenario: policy, thresholds, load, patients, heterogeneity, seed (key=value args)
  EHealthController.java           writes the per-run CSV files when the simulation ends
  TrackedSensor.java, Metrics.java, NetworkBytes.java,
  SeededExponentialDistribution.java, SeededBernoulliSelectivity.java
  scripts/run_experiments.py       campaign E1-E4 (380 runs, 10 seeds), parallel and resumable
  scripts/summarize_runs.py        results/E*/ -> revision/results_summary.csv and revision/latency_hist.csv
  scripts/make_figures.py          revision/results_summary.csv -> figures and Table 6 of the manuscript
run_campaign.sh                    compiles src/ into build/ and runs the whole campaign
revision/                          per-run summary of the 380 runs, aggregated tables, calibration runs, figures
```

## Reproducing the results (Java 21, Python 3 with numpy, pandas, scipy and matplotlib)

```bash
bash run_campaign.sh                                    # about 1 h on an 8-core laptop; writes results/E1..E4
python3 src/org/fog/test/perfeval/ehealth/scripts/summarize_runs.py
python3 src/org/fog/test/perfeval/ehealth/scripts/make_figures.py revision/results_summary.csv revision/figures
```

Single run (a few seconds):

```bash
java -cp "build:jars/*:jars/commons-math3-3.5/*" org.fog.test.perfeval.ehealth.EhealthFogV2 \
     policy=CRITICALITY_AWARE load=1.2 seed=1 out=results/test/ca
```

Policies: `LOCAL`, `ALWAYS_FOG`, `CRITICALITY_AWARE`. Main parameters and defaults: `threshold=0.7`,
`fogThreshold=0.8`, `window=100` (ms), `patients=50`, `edgeMips=3000` (or `hetero` for 2500/3000/4000),
`anomaly=0.05`, `load=1.0`, `criticalMI=10000`, `fogMips=10000`, `simTime=10000`, `warmup=1000` (ms).

The raw per-tuple files of the campaign (`results/E*/`, about 1.2 GB) are not stored in the repository; they are
regenerated by `run_campaign.sh` with the same seeds.
